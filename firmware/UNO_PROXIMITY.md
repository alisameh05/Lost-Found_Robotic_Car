# Uno R3 HC-SR04 advisory

## T2 identity and build

The selected HC-SR04 connects to the Uno R3 on D12 (trigger) and D13 (echo). The Uno publishes observations through the selected HC-05 command transport. The same backend worker owns the open link and checks the Uno build ID against its correlated HELLO before accepting observations. The Windows transport uses the exact private endpoint from `hc05_uno.identity`. The [pending interface manifest](../backend/device/interfaces.pending.json) records the source and protocol.

Use the pinned Uno toolchain from the [command build record](../backend/PHASE_07_COMMAND.md). Add an explicit `proximity_sample_interval_ms` to the build mapping to enable the sensor. The build validates the 60–60,000 ms interval and rejects motor pin conflicts. Its generated artifact records the proximity protocol, pins and interval with the exact build ID and firmware hash. Edge interrupts measure the echo while command parsing and expiry continue. The loop issues a 10 µs trigger and bounds the echo window to 30 ms. No echo or a pulse yielding zero millimeters reports invalid.

## T6 observation contract v1

[Machine-readable contract](uno/proximity.v1.json)

- An optional 23-byte frame starts with route byte `0x01`, followed by the COBS-encoded body and little-endian CRC16-CCITT-FALSE, then a zero delimiter. The route byte distinguishes observations from command frames. STATUS and DRIVE can each carry one newly acquired sample after the ordinary ACK. Command ACK fields and validation stay the same. The UART discards telemetry if it cannot queue the complete frame. Control timing for a build with telemetry needs its own measured evidence.
- The frame contains version, nonzero Uno boot generation, the correlated ACK's nonzero successor challenge, nonzero sample sequence within that boot, conservative elapsed milliseconds from trigger to ACK creation, validity, and integer distance in millimeters. Invalid observations carry zero distance. Valid wire distances are bounded to 1–6000 mm and must also fall in the narrower measured Device range.
- The worker binds the sample to the preceding verified ACK. It subtracts the reported age from the earliest possible ACK creation time, the host request-send timestamp. The measured deadline includes transfer, buffering, host projection and the time that has elapsed since then. Missing, oversized, malformed, incompatible, replayed, old-boot, out-of-range and stale samples cannot clear a warning. During an interruption the workspace shows Unknown with no distance and retains the previous warning latch.
- The workspace uses its existing snapshot and `proximity_warning_changed` event. While a subscriber send is blocked, the backend retains the current advisory for snapshots and defers issuing another advisory sequence until subscribers can accept it. Required events retain their waiting queue. The advisory does not change session revision, readiness, motion permission or commanded direction. A failure of the shared command path still follows the existing required-path recovery rules.

## T4 calibration

Alisa observed continuous readings from about 15 to 750 mm on the reference sketch. That observation supplies a starting span for the bench. The candidate test settings are a 200 ms trigger interval, a 200 mm warning boundary, a 300 mm clear boundary, three consecutive clear readings, and a 900 ms freshness deadline. Confirm the usable range and choose final values from repeated observations of measured targets with the selected mounting and link. Record target distances and geometry, observed distances and conservative ages, invalid/timeout cases, warning and clear transitions, and the selected build and endpoint. Verify command timing with telemetry enabled on the selected link.

For a qualified Device bundle, set `hcsr04.source` to `uno-r3`, `transport` to `uno-command`, `unit` to `mm`, and `protocol_version` to 1. Set `endpoint_id` and `uno_build_artifact_sha256` to the exact command selection, and `contract_sha256` to the SHA-256 of the contract file bytes. Set `minimum_distance_mm` and the five proximity profile bounds to measured values. Reference the SHA-256 of a version 1 `HcSr04Calibration` artifact in `calibration_artifact_sha256`. The artifact records `profile_id`, `uno_build_artifact_sha256`, `procedure_id`, `result_sha256`, and a `bounds` map containing the five profile bounds, `proximity_min_distance_mm`, and `proximity_sample_interval_ms`.

The result is a version 1 `HcSr04DeviceResult` with `source_identity`, `endpoint_id`, command `transport`, `uno_build_artifact_sha256`, test `conditions`, and `readings`. Each reading records `target_mm`, `distance_mm`, conservatively rounded-up `upper_age_ms` and the displayed `state`. Include fresh, in-range Warning and Clear observations that support the qualified thresholds. Store the contract, build, calibration and recorded results under the private Device artifact directory.

### Motor-disabled USB bench, 2026-11-23

The identified Uno on Windows COM7 verified the upload of the USB build with SHA-256 `6a3e6055de556d57d83b50527306e8a105b6eda1b8f769cee1cbe0f77c9c3177`. The motor battery was disconnected. The production decoder and advisory logic received 288 observations in the 60-second run, with conservative USB observation ages of 99–201 ms. With an object near the sensor, 26 mm produced Warning. A 2516 mm reading produced Unknown with the warning still latched. The next three observations were 302, 569, and 301 mm. Only the third produced Clear. A subsequent 2520 mm reading produced Unknown. The targets were moved by hand and the reference distances were unrecorded. These results verify the firmware, USB path and advisory response; the measured Device range and settings require controlled target distances and qualification on the selected link.

### Motor-disabled HC-05 bench, 2026-11-23

The selected Windows BLE endpoint connected to the Uno UART on D2/D3 at 9600 baud. COM7 verified the upload of the motor-disabled BLE build with SHA-256 `c8f7a5ea10f2f8ea641e62384e4cf9d1c785d97fa1cc125030d905ce1c84f2cf`. Correlated HELLO verified its identity and a disarmed output. With the target in place, the first 49 mm reading produced Warning. Nine advisory readings in that run produced Warning, with conservative ages of 322–451 ms. A separate run produced Unknown for six invalid readings. Both runs experienced a STATUS acknowledgment timeout.

During the later target adjustment, the diagnostic recorded 54 STATUS acknowledgments at 116–267 ms and 41 Unknown observations at conservative ages of 350–643 ms. Eighteen STATUS attempts were interrupted by a send deadline or acknowledgment timeout before the BLE notification stream became unavailable. Clear was observed over USB, and the protected replay verified the full clear rule. BLE command timing for this build and controlled target distances remain open for the Device profile. The Uno remains on the motor-disabled BLE image.

The protected synthetic replay can exercise threshold equality, hysteresis, invalid and stale observations, sustained clear, and continued manual control without the device. The synthetic values and motor-disabled builds are bench evidence. The Device projection remains Unknown until the selected production build and measured calibration pass configuration validation and supply fresh samples.
